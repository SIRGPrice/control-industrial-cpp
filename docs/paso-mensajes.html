Colas

Paso de mensajes

Hay dos filosofías para comunicar hilos: compartir variables (protegidas con semáforos o mutex) o pasarse mensajes por colas. En plantas grandes el paso de mensajes produce diseños más limpios: cada estación es una caja que recibe órdenes y emite eventos, y las colas son las cintas virtuales que las unen.

Memoria compartida frente a mensajes

Memoria compartida + semáforosPaso de mensajes (colas)
AcoplamientoLos hilos conocen las variables de otrosSolo conocen el tipo de mensaje
SincronizaciónExplícita y propensa a erroresImplícita: el push/pop ya bloquea
TrazabilidadHay que instrumentar las variablesEl registro de la cola ES la traza
Ideal paraSeñales simples, recursos únicos, contadoresFlujos de trabajo, piezas, órdenes, telemetría

En la práctica se mezclan: semáforos para los recursos físicos únicos (el robot, el horno) y colas para el flujo de piezas y mensajes.

Diseño de mensajes

Un mensaje es un valor que viaja entero de un hilo a otro: una vez enviado, el emisor no lo toca. En planta suelen ser structs pequeños con std::variant para las uniones de tipos:

#include <cstdint>
#include <variant>
#include <string>

struct Pieza {
    uint32_t serie;          // número de serie (lector de códigos)
    int prioridad;           // 0 = normal, 1 = urgente
};

struct Alarma {
    int codigo;              // p. ej. 14 = sobrecalentamiento M2
    std::string texto;
};

struct Orden {
    enum class Tipo { Arrancar, Parar, CambiarConsigna };
    Tipo tipo;
    double valor;            // consigna nueva si procede
};

// El buzón de una estación acepta varios tipos:
using Mensaje = std::variant<Pieza, Alarma, Orden>;

Los tres buzones típicos de una estación

  • Cola de entrada de piezas (ColaBloqueante<Pieza>): lo que la estación anterior le entrega.
  • Cola de telemetría/eventos hacia el supervisor: fin de pieza, avería, contadores.
  • Cola de órdenes desde el operador/SCADA: arrancar, parar, cambiar consigna.
ColaBloqueante<Pieza>  colaEntrada(4);   // piezas desde la estación anterior
ColaBloqueante<Evento> colaEventos(32);  // hacia el supervisor
ColaBloqueante<Orden>  colaOrdenes(8);   // desde el operador

void hEstacion(std::stop_token parada) {
    while (!parada.stop_requested()) {
        Orden orden;
        if (colaOrdenes.popDurante(orden, std::chrono::milliseconds(200))) {
            atenderOrden(orden);          // primero, las órdenes del operador
            continue;
        }
        Pieza p;
        if (colaEntrada.popDurante(p, std::chrono::milliseconds(200))) {
            procesar(p);
            colaEventos.push({Evento::Tipo::PiezaTerminada, p.serie});
        }
    }
}
📘 Nota

popDurante (pop con timeout, visto en Colas) es lo que permite a un hilo atender varias colas sin quedarse dormido para siempre en una de ellas: espera un poco en cada una por turnos.

Jerarquía de mensajes en una planta

El patrón resultante es un árbol: los hilos de estación hablan entre sí por colas de piezas, y todos informan hacia arriba al supervisor por colas de eventos, recibiendo órdenes por sus colas de órdenes. En Arquitectura de control se desarrolla el esquema completo, y el laboratorio de colas muestra un supervisor consumiendo telemetría en vivo.

Reglas prácticas

  • Los mensajes se pasan por valor (o std::move): nada de punteros a memoria del emisor.
  • Mensajes pequeños y autodescriptivos: serie, tipo, marca de tiempo.
  • Una cola por relación emisor–receptor; si dos estaciones necesitan prioridad, dos colas con un try_pop primero sobre la urgente.
  • Las colas de eventos hacia el supervisor deben ser de capacidad generosa: una avería puede generar ráfagas.
